### 功能

​	`sys_linkat`实现了对同一个文件创建两个链接方式。实现原理是去 root 目录下找到原有文件对应的 Inode 的序号，根据序号和新名字，在 root 目录的 DiskInode 上写入一个新的 DirEntry 作为映射，同时增加一次文件对应 Inode 的引用计数。

​	`sys_unlinkat`实现了对一个硬链接的取消。实现原理是简单地把 root 目录下对应的 DirEntry 给设为空，然后把对应 Inode 的引用计数减一，如果减为 0 了，就把这个文件删了。

​	`sys_stat`实现了查询一个 fd 对应的文件信息。实现原理是对 File 这个 trait 新增一个 stat 的方法实现，返回 Stat 这个结构体。stdin 和 stdout 返回值都定义为了 NULL 和 0，由 OSInode 管理的文件则调用 easy-fs 里面定义了的函数去磁盘进行查询并返回。

### 简答作业

#### ch6

Q：在我们的easy-fs中，root inode起着什么作用？如果root inode中的内容损坏了，会发生什么？

A：root inode 充当了 os 访问磁盘的桥梁，存了所有存在磁盘上文件的名字和地址，操作系统需要访问文件的时候就要先在 root 里找地址再去查。
如果 root inode 损坏了，就不能准确定位到文件的数据，导致操作系统需要访问磁盘数据的时候就会出错。



#### ch7

Q：举出使用 pipe 的一个实际应用的例子。

A：通过 

```
cat a.txt | wc -l
```

来获取 a 这个文件的行数，就是通过 | 创建了一个管道，写端是 a.txt 读出来的内容，读端是 wc 接收的数据。



Q：如果需要在多个进程间互相通信，则需要为每一对进程建立一个管道，非常繁琐，请设计一个更易用的多进程通信机制。

A：在进程之间弄一个类似于中转站的地方，里面有一个队列，每个元素记录这个数据从哪个进程发到哪个进程，发送和接受过程由中转站控制，每个进程只需要发或者接。
